# Phase 2 — Repository Understanding

## Goal

Build the current-system model so the product can answer:

> **What is this software and how does it work today?**

## Prerequisites

Phase 1 complete.

## Tasks

- GitHub App
- repository metadata
- deterministic ingestion
- Tree-sitter/code analysis
- symbols
- dependencies
- test relationships
- architecture relationships

## Key Output

A queryable model of the current software system.

## Definition of Done

A connected repository can expose:
- major components,
- dependencies,
- APIs/symbols,
- tests where detectable,
- architecture relationships.
